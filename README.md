# dates

## コンバージョンの先にあるもの

デートをマーケティング・オントロジーから語り直す。

マーケティングでは、認知、興味、検討、コンバージョン、離脱という概念で人の行動を捉える。

しかしデートは、単純なファネルではない。

```text
好感
 ↓
期待
 ↓
葛藤
 ↙   ↘
進みたい  戻りたい
 ↘       ↙
  もう一度考える
       ↓
   もっと / もう
```

人の心理は、すぐには落ち着かない。
好きだから進むとは限らない。好きだから迷うこともある。

だから重要なのは、コンバージョンしたかどうかだけではなく、**なぜもっとになったのか、なぜもうになったのか**である。

## 最短ではゴールに着かない

デートの価値は目的地だけにない。

寄り道、偶然、待ち時間、どうでもいい会話、少し遠回りした道。その途中で二人の状態が変化していく。

**必要な摩擦まで消してはいけない。**

ゴールから逆算する。しかし、最短では行かない。

## わくわくを共有する

デートでは、期待を一方的に与えるのではなく、二人で未来を想像する。

「ここ行ってみようか」

「このあと面白いところあるよ」

「もう少し歩いてみる？」

わくわくは共有される。

だからデートを支援するAgentも、次の場所を最短で提示するだけではなく、次の可能性を少しだけ見せる。

全部を決めない。少しじらす。ゴールまでの余白を残す。

ただし、じらしすぎれば「もう」になる。

## 離脱を失敗にしない

「もう帰りたい」は失敗ではない。

それも二人の体験が到達した一つのゴールである。

コンバージョンを最大化するのではなく、**二人の心理変化を観察し、葛藤を消さず、次の可能性をそっと提示する。**

## デートとは何か

デートとは、二人の間に生まれる小さなファネルではない。

**二人が一緒に歩く、分岐だらけのプロセスである。**

マーケティングの世界では、コンバージョンは目的地だった。

人間の世界では、価値があるのはコンバージョンそのものではなく、そこへ向かう途中で二人の関係がどう変化したかである。

## Blueprint — 客観化する世界

このプロジェクトでは、デートを「成功させる方法」だけを設計しない。

人と人の間に何が起きているのかを、少し離れて眺めるための**客観化の装置**を構想する。

### 親密度を測る

親密度は目的の一つである。しかし、親密度そのものを直接知ることはできない。

相手が何を感じているか、二人の関係がどこまで進んでいるかは、完全にはわからない。

だからAgentは「親密度は 83 点」と断定するのではなく、会話、反応、時間、行動、共有した体験などから、**そうかもしれない状態を推測する**。

```text
観測できるもの
  ↓
会話 / 反応 / 行動 / 時間 / 体験
  ↓
解釈
  ↓
親密度の仮説
  ↓
次の可能性を想像する
```

### デートと他者は「わからない」

この世界では、他者の内面をデータとして完全に取得できるとは考えない。

「わからない」を欠陥ではなく、設計上の前提にする。

だからAgentの役割は、他者を断定することではなく、

**観察する → 客観化する → 想像する → 計画する → また観察する**

という循環をつくること。

### Chatも親密度を変える

親密度が変化するのは、実際に会って移動したときだけではない。

Chat、電話、メッセージ、共有したリンク、写真、音楽、沈黙なども、関係を変化させる行為になりうる。

```text
Chat
 ↓
関係の変化
 ↓
想像
 ↓
おでかけ
 ↓
共有体験
 ↓
Chat
 ↓
また関係が変化する
```

したがって、`odekake` は親密度そのものではない。

**odekakeは「移動と体験」を扱い、親密度はその過程で起こりうる目的・状態変化として扱う。**

### 想像して、計画する

わからないからこそ、いくつかの可能性を想像する。

- 今日は少し距離が縮まるかもしれない
- この店なら会話が生まれるかもしれない
- この展示を見たら新しい話題が生まれるかもしれない
- 逆に、今日はここで帰るほうがいいかもしれない

Agentは唯一の正解を出すのではなく、観測された事実と想像された可能性を分けながら、次の行動を計画する。

### すべてがある

`dates` の世界では、Chat、デート、移動、場所、作品、会話、期待、葛藤、親密度、離脱、想像、計画を一つの世界の中に置く。

ただし、それらを一つのスコアに潰さない。

```text
                 ┌── Chat
                 │
観察 ──→ 客観化 ┼── Date
                 │
                 ├── Odekake
                 │
                 ├── 想像
                 │
                 └── 計画
                        ↓
                   次の体験
                        ↓
                     また観察
```

目指すのは「相手を攻略するAgent」ではない。

**わからない他者と、自分自身との間に起きていることを客観化し、それでもなお想像し、次の可能性を計画できるAgent。**

これは実装仕様ではなく、`dates` が今後どんな機能やAgentを生み出しても戻ってこられるための**世界観・Blueprint**である。
